# MCP4822 function reference

Source: `src/libs/MCP4822/` (written for this project, like the AD5452 driver).
Drives the Microchip MCP4822 dual 12-bit voltage-output DAC over SPI.
Datasheet: MCP4802/4812/4822, DS20002249.

One chip holds the DC offset for both generator channels: `VOUTA` = CH1,
`VOUTB` = CH2 (`OFFSET_DAC_CHANNEL` / `OFFSET_DAC_CHANNEL_2` in `config.h`).
Each `FunctionGenerator` gets the shared CS pin plus its own channel and only
ever writes that channel.

The output is `Vout = 2.048 V × code / 4096 × gain`, gain 1x or 2x, from the
chip's internal reference. It can't go above VDD, so on 3.3 V at 2x gain the
codes above about 3250 clip. The firmware uses 2x (1 mV per code) because the
offset stage (offset = 3.0 × Vdac − 5 V) needs up to 3.2 V, and never sends a
code above `OFFSET_DAC_CODE_MAX` (3200 = +4.6 V). +5 V would need about 3.33 V,
which is why the offset range stops at +4.6 V.

## Public API

| Call | Returns | Description |
|---|---|---|
| `MCP4822(uint8_t csPin, SPIClass* spi = &SPI, uint32_t spiHz = 8000000)` | n/a | Stores the pins. Nothing touches the hardware yet. |
| `begin()` | `void` | Sets CS as an output, idle HIGH. **Does not start the SPI bus**; `FunctionGenerator::begin()` does that. |
| `write(uint8_t channel, uint16_t code, bool gain2x = false)` | `void` | Sets one channel and turns its output on. Codes above 4095 are clamped. Any channel other than `CHANNEL_A` counts as `CHANNEL_B`. |
| `shutdown(uint8_t channel)` | `void` | Shuts one channel down (output pulled to GND through ~500 kΩ, like at power-on). Not used by the firmware. |
| `code(uint8_t channel)` | `uint16_t` | Last code written to that channel (0 before the first write or after a shutdown). The chip has no readback. |
| `CHANNEL_A` / `CHANNEL_B` | `0` / `1` | `VOUTA` / `VOUTB`. |
| `MAX_CODE` | `4095` | Full scale. |
| `DEFAULT_SPI_HZ` | `8000000` | The chip allows up to 20 MHz; `config.h` sets `OFFSET_DAC_SPI_HZ`. |

## SPI details

One 16-bit word per write, MSB first, inside one CS-low frame:

```
A/B  -  GA  SHDN  D11 D10 D9 D8 D7 D6 D5 D4 D3 D2 D1 D0
```

- `A/B`: 0 = DAC A, 1 = DAC B.
- `GA`: 1 = 1x gain, 0 = 2x gain.
- `SHDN`: 1 = output on, 0 = that channel shut down.

Data is latched on the rising SCK edge (SPI mode 0 or 3; the driver uses
`SPI_MODE0`). With `LDAC` tied to GND the output changes as soon as CS goes
high. Each write sets its own `SPISettings`, so the chip shares the generator
bus with the AD9833 (`SPI_MODE2`) and the AD5452 (`SPI_MODE1`).

## Gotchas

- **Power-on state is both channels shut down** (about 0 V out). With the offset stage that is about -5 V at the output, so the output sits there until `FunctionGenerator::begin()` writes the 0 V code. Both channels' `begin()` run right after the safe pin states at the top of `setup()`, so both channels get their 0 V code before anything else happens.
- **Not linear at the ends.** The DAC isn't linear right at code 0 or near VDD, which is why the offset is calibrated at two codes inside the range (`OFFSET_CAL_CODE_LOW` / `_HIGH`), not at 0 and 4095.
- **No ratiometric reference.** The 2.048 V reference is the chip's own, not the +5 V that sets the -5 V shift in the summer, so the two don't drift together. Calibrate on the built board.
- **Floating CS before `setup()`.** A 10 kΩ pull-up on CS keeps the chip deselected until `setup()`, and `holdSafePinStates()` drives it HIGH from then on. Because the pin is already an idle-high output, `begin()` never blips it LOW.
- **Decoupling.** 100 nF from VDD to GND at the chip.

## Typical use

```cpp
MCP4822 dac(PIN_OFFSET_DAC_CS, &SPI, OFFSET_DAC_SPI_HZ);
SPI.begin(PIN_GEN_SCK, PIN_GEN_MISO, PIN_GEN_MOSI);   // PIN_GEN_MISO is -1: no MISO
dac.begin();
dac.write(MCP4822::CHANNEL_A, 1470, true);   // 1.47 V at 2x gain
uint16_t now = dac.code(MCP4822::CHANNEL_A);
```
